# Geist Home Assistant integration

This custom integration supports Geist devices that expose either the legacy
XML endpoint or the newer token-authenticated JSON API.

## Setup

Add **HA Geist** from **Settings → Devices & services → Add integration**.
Enter the device URL (for example, `http://192.168.1.50`) and an account
supported by the device. The integration detects the API type while validating
the connection. Devices with known Geist MAC address prefixes can be offered
through DHCP discovery; manual host entry remains available.

Use an account with control permissions if you want to operate relays. The
integration keeps the API token in memory and stores the configured username
and password in the Home Assistant config entry.

## Entities

The legacy XML API creates sensors from each device's `<field>` elements. The
JSON API creates sensors from device measurements and analog inputs, and a
switch for each relay. Relay switches send explicit on/off commands and refresh
the device state afterward. Data is polled every 30 seconds. Debug logs summarize
the host, friendly name and JSON device, measurement, relay and alarm counts
without logging credentials.

Configured alarms are exposed as read-only sensors. Their names include reported
thresholds.
XML and JSON alarm sensors are added and removed as device configuration changes.
For JSON devices, a control-enabled account also exposes an acknowledgement
button for each alarm. It is available while the alarm is tripped or
latched and does not resolve the underlying fault.
Digital inputs from the JSON API are binary sensors. Known JSON measurement
names follow the XML naming style. Temperature and dewpoint sensors provide both Celsius and
Fahrenheit when the source unit is known; converted values are rounded to two
decimal places.

Attached devices are named after their host and linked to it as connected
devices, so their entity IDs include the host name, for example
`BB100 - Office Digital Sensor` (JSON) or `Entertainment Center RSM Temp Sensor`
(XML). The host is the XML device with index 0, or the JSON device matching the
controller's reported model.

Entity IDs are generated by Home Assistant from the device name and entity name
(for example `sensor.entertainment_center_rsm_temperature`). An ID is fixed when
the entity is first registered, so later renames on the device or in Home
Assistant do not change it.

SNMP discovery is not currently used. Discovery does not scan network ranges.

## Development

Run `scripts/develop` to start the local Home Assistant instance. Run
`ruff check .` and `pytest` to lint and test the integration.

## Integration structure

Module | Purpose
-- | --
`manifest.json` | Integration metadata, including the DHCP MAC prefixes used for discovery.
`config_flow.py` | Setup, reconfiguration and DHCP discovery. Tries the XML API first, then the JSON API, and stores the detected type in the config entry.
`__init__.py` | Entry setup: creates the client for the stored API type, the coordinator, and the entity platforms.
`api_xml.py` | Client and parser for the legacy HTTP `/data.xml` API.
`api_json.py` | Client and parser for the token-based JSON API, including alarms, relays and alarm acknowledgement.
`exceptions.py` | Error types shared by both clients.
`types.py` | Dataclasses for parsed XML and JSON data.
`coordinator.py` | Polls the selected client every 30 seconds and keeps device registry details such as firmware current.
`data.py` | Runtime data stored on the config entry (client, coordinator, integration).
`entity.py` | Base entity class that uses device-based entity names.
`sensor.py` | Measurement and alarm sensors for both APIs.
`binary_sensor.py` | Digital inputs (JSON).
`switch.py` | Relay control (JSON).
`button.py` | Alarm acknowledgement buttons (JSON).
`const.py` | Domain, logger and API type constants.
`translations/` | UI strings.

### Data flow

1. The config flow detects whether a device speaks XML or JSON and saves the choice.
2. On setup, the matching client is created and the coordinator performs a first refresh.
3. The coordinator polls the client; every entity reads its value from the coordinator's data.
4. The platforms create entities from the first refresh. JSON alarm sensors and buttons are added or removed as alarms change on the device.

## Changelog

### 0.1.0

- Monitor legacy XML (`/data.xml`) devices and newer token-authenticated JSON
  devices, with the API type detected during setup and reconfiguration.
- Sensors for measurements and configured alarms, binary sensors for digital
  inputs, relay switches and alarm acknowledgement buttons (JSON).
- Celsius and Fahrenheit temperature and dew point sensors for JSON devices.
- Entity IDs are generated by Home Assistant from the device and entity names.
- Attached sensors are named after and linked to their host device.
- DHCP discovery by Geist MAC prefixes, configurable entry names and a reconfigure flow.
- Requires Home Assistant 2026.2.0 or newer.
